# 夸克先压缩再上传

目标：每个已选择的上传任务生成一个 ZIP；同一内容重复执行时跳过云端已有包，避免逐文件上传产生重复文件。

采用每任务一个完整快照包，沿用现有云端任务目录及排除规则。ZIP 内保留目录结构、中文文件名和空目录，固定排序、时间与权限，并使用整个包的 SHA-256 命名。云端文件名及大小一致时跳过；返回 MD5 时额外校验。内容改变后生成新的完整包，保留历史包和已有散文件，不进行云端删除。

压缩包存于自动清理的临时目录，分块压缩、校验和上传，支持暂停与停止。共享已有符号链接检查，拒绝链接和目录联接；打包失败或停止不发起上传。界面增加打包阶段，云端进度按压缩包计数。

改动范围：`quark.rs` 的打包、上传及测试；`backup.rs` 仅开放现有链接检查供打包复用；`main.rs` 接入阶段进度；`app.js`、`index.html` 提示；`Cargo.toml`、`Cargo.lock` 增加 ZIP 依赖；README 补充行为说明。

验证：`npm test` 40 项通过，包括 ZIP 解压内容、稳定摘要、排除规则、中途停止和两次同步仅上传一个 ZIP 的模拟接口测试；`npm run check` 通过。使用项目已有的 MSVC 兼容库目录作为 `_LINK_` 搜索路径。真实账号云端上传尚未验证。

界面验证：`tools/ui-smoke.cjs` 使用独立截图输出目录 `artifacts/quark-zip-ui` 执行通过，覆盖登录重试、任务选择、同步进度、五种主题及 1120 / 920 宽度布局；原截图目录写入失败，未覆盖已有产物。
